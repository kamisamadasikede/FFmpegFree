## 1. 原则
1. **数字员工群，不是流水线聊天**：中栏以任务卡 → 派活灰字 → 短复 / 汇报卡为主；不做左右气泡。互不依赖的活**并行**，不为填栏目硬串人。
2. **干活过程不进消息流**：流式正文、思考、工具调用只在「查看过程」抽屉 / 成员自己的会话里。
3. **Cat 居中**：员工之间不直接对话；文件列表由 Cat 填，不让模型自述。
4. **@ 自主**：谁接着干，由用户或成员在群里 / 汇报「交给谁」里自己 @；**无系统强制流水线**。空「交给谁」= 结束，不自动请下一位。
5. **回复对标 Grok Bot**：短、有用、没事可沉默。只有正式交付才出汇报卡；招呼 / 澄清用短自然语言回复。
6. 一期不出现：成员私聊、跨项目群聊、定时开工、并行改同一文件的橙色提醒、「发给: 全体」。

## 4. 左栏：项目下的群聊
- 项目展开后在会话列表之上出现分组「群聊 · n」，分组行右侧「+」新建群。每个项目可以有多个群。
- 群项：橙色 users 图标（`--cat-orange`）+ 群名 + 右侧叠放头像（≤3 + “+n”）。
- 状态点（群名右侧 6px）：有人在干活 = 主色呼吸点（忙）；有失败未处理 = 红点；有越界未处理 = 橙点。

## 5. 新建群（680 宽）
1. **群名**（1–40 字，必填）。
2. **成员**（可拖动排序；排第一的成员 = **关了自动派活时**的兜底接手人，底部灰字说明）。每行：拖动柄 · CLI 选择（Grok Build / Claude / Codex）· 职位 · 模型（可选，默认该 CLI 默认模型；列表与设置页 / 单聊同一套 `listCatModels`）· `@名字`（群内唯一）· 删除。
   - 重名：输入框下 12px `--ff-danger`「群里已经有叫这个名字的成员了」，并给建议「后端工程师 2」（同职位第二个自动推荐）。
   - **没有默认协调者**；全员共用项目文件夹。
3. 底部：「取消」「创建」。创建后成员立即可用，职责规范后台生成。

### 5.1 职责规范卡（自动生成）
段落：**负责** / **不碰** / **负责的目录** / **做完 @** / **交付物** / **完成标准**。
- 负责的目录：等宽字体 chip，橙色描边醒目；空 → 灰字「没写目录，不做越界检查」。
- 操作：「编辑」「重新生成」。
- 生成中：骨架 + 「正在生成职责…」。失败：灰字「职责还没生成」+「重新生成」。
- 用户手改过的段，段标题旁标「已手动修改」（加人/减人只重算「做完 @」段，手改段永不覆盖）。
- 职责生成用**该新成员自己那家 CLI** + 其模型（6.21.15 ②-1）。
- **做完 @（v0.2.4）**：默认不交下一位；只有真有依赖或要并行专家时才写 @；禁止为填栏目硬 @。

## 6. 中栏：工作汇报群
顺序：**任务卡**（用户消息，`--cat-accent-soft` 底，全宽）→ **派活灰字** → **短复 / 汇报卡** → …

### 6.1 汇报卡（字段 6.21.15）— 仅正式交付
| 区 | 内容 | 规则 |
|---|---|---|
| 头 | 头像 · 名字 · 职位 · CLI 标签 · 时间 | 点头像 = 查看过程 |
| 完成了什么 | `did` | 必有 |
| 改了哪些文件 | `files[]`（Cat 填） | 默认收起，标题行「{n} 个文件 +a −d」；展开逐行路径 + `+a −d` + 标签（越界 / 来源不明） |
| 需要注意 | `attn` | 空则整段不显示；橙色三角图标 |
| 交给谁 | `give` | **可空**；空则整段不显示；有则 @chip（`--ff-primary`）+ 要做什么；写了 @ = 成员自己决定请谁接着（仍唤醒） |
| 底 | 完成于 {时间} · 输出 {n} token · {x} token/s ·「查看完整过程」 | |

**没按格式**（`parsed=false`）：若内容仍属正式交付，只显示「完成了什么」（= 最后一段原文）+ 灰字「没按汇报格式写，只显示最后一段回复」。招呼 / 澄清见 6.1a，**不要**硬套四段卡。
消息正文中已识别的 `@名字` 用 `--ff-primary`；未匹配的保持普通文字。

### 6.1a 短自然语言回复（v0.2.4）
- **何时**：招呼、澄清、一句确认、无需交付物——对标 Grok Bot，短、有用、没事可沉默。
- **长什么样**：头像 · 名字 · 时间 + 一段自然语言正文；**无**「完成了什么 / 改了哪些文件 / 需要注意 / 交给谁」四段结构，也不出现「没按汇报格式」提示。
- **何时改用汇报卡**：有正式交付（改了代码 / 写了方案 / 跑完用例等）才出汇报卡。

### 6.2 干活中（输入框上方状态条）
- 每人一行：头像 ·「{成员} 正在干活 · 已用 {时长}」+（有工具时）「 · {n} 个工具」· 按钮「查看过程」「停止」。
- 多人时底部汇总：「{N} 人在干活」+「全部停止」。
- 「查看过程」= 右侧抽屉，显示该成员本轮工具调用 + 流式输出，只看 / 停止，不可输入。抽屉副标题可保留内部 hop 次数（如「第 2/6 次」）；**消息流灰字不写第 n/6**。

### 6.3 失败 / 停止（消息流灰字，不发汇报卡、不自动请下一位）
- 失败：「{成员} 没完成：{原因}」+「重试」（同链同任务再跑一轮，**hop 不加**）+「查看过程」。
- 停止：「{成员} 已停止」；换人触发的括注「（换人时停下的）」。

### 6.4 派活灰字（12px `--ff-text-2`，`systemKind=route` 等）
| 时机 | 文案 |
|---|---|
| 判断中 | 正在安排谁来接… |
| 判断出 | 交给 {成员}：{理由≤20字} |
| 追问 | 交给 {成员}：接着上一条 |
| 判断失败 / 超时 / 定不出（v0.2.3，产品 A） | 没判断出该谁接，请 @ 对应成员，或再说具体要做什么。（可带「· 判断用时 n 秒」；**不起成员、不交给排第一**） |
| 自动派活关 | 交给 {成员}：没开自动派活，交给排第一的成员 |
| 用户换人后 | 交给 {新成员}：你指定的 |
| 成员在「交给谁」写了 @（v0.2.4） | 已请 {成员} 接着（**不写第 n/6 次**；无「接力」字样） |
| 「交给谁」为空（v0.2.4） | **可不显示灰字**；若需状态反馈，弱灰字只写「{成员} 已完成」（**不写**「没有交给下一位」） |
| hop 到 6 | 已连续请人 6 次，先停在这里。需要继续请 @ 对应成员。 |
| 换人 | 已换人：{原} → {新} |
| 目标成员正在干活（排队，v0.2.2） | 交给 {成员}：正在干活，排在后面 |

- 派活类灰字行尾「换人」（下拉选成员）；**判断失败 / 超时 / 定不出那行不出现「换人」**（v0.2.3）。换人时原成员若在跑 → 停下，状态「已停止」。
- 判断失败时不发汇报、不起成员干活、不自动交给排第一（v0.2.3 产品 A）。
- 点灰字展开详情小卡：看了这条 + 最近 10 条 + 成员职责；原样 JSON 输出；CLI / 耗时。
- 用户消息自带 @ → 直接**并行**叫醒，不出「你指定的」。
- **无系统强制流水线**：空「交给谁」不自动请下一位；只有用户或成员写了 @ 才继续。

## 7. 越界与撤销（`--cat-orange`）
- 汇报卡左侧 3px 橙条；文件区上方「改了不属于自己的文件（{n} 个）」可展开，超过 3 个折叠「还有 N 个」。
- 文件后橙色小标签「越界」；灰色小标签「来源不明」，悬停「这段时间有多人在干活，不确定是谁改的」，不可撤销。
- 按钮「撤销这些改动」→ 确认框：标题「撤销 {成员} 的越界改动？」，灰字「只撤销这 {n} 个文件在这一轮的改动，其他文件不受影响。」，按钮「撤销」（danger）「取消」。
- 成功 toast「已撤销 {n} 个文件的改动」；冲突红字「{文件} 之后又被改过，不能自动撤销，请手动处理。」

## 8. 输入框
- 只有「+」（附件）/「@」/「发送」；**无「发给: 全体」**（v0.2.1）。
- 「@」或键入 @ 弹层，标题「@ 成员」，列出头像/名字/职位/状态；选中插入整体 chip，退格整删。

## 9. 右栏
- tab「成员」「文件」。
- 成员：头像 · 名字 · 职位 · CLI · 状态（空闲 / 正在干活 / 排队中 / 越界橙点）· 单停；拖动排序；底部说明「排第一的成员负责兜底：关了自动派活时交给他」（判断失败不再兜底，见 v0.2.3）。
- 状态文案（v0.2.2，逐字）：「空闲」「正在干活」（不用「干活中」）「排队中 · 前面还有 {n} 个」「越界待处理」「已停止」「没完成」。
- 排队中：文案较长，放在名字下面第二行（替换「职位 · CLI」），颜色 `--cat-warn-text`；右侧保留单停按钮（取消排队）。`{n}` = 排在他前面的任务数，从 1 起；数据等契约 v0.55.6。
- 群设置：群名、成员排序、开关「没 @ 人时自动派活」（默认开）、删除群。

## 10. 待对齐 → 已定（契约 6.21.15 ② / v0.56）
1. ✅ 派活判断用**排第一成员**那家 CLI + 其模型；超时 20s；无工具；不落 SessionID。
2. ✅ 职责规范生成用**新成员自己**那家 CLI + 其模型；超时 60s；JSON Schema。
3. ✅ 一条回复 @ 两人：hop **+1**；两人**并行**开工。
4. ✅ 汇报 schema：`did` 必填，`attn` / `give` 可选；文件列表不进 schema。
5. ✅ 重试：同链同任务再跑一轮，hop **不加**。
6. ✅ 并行改同一文件的橙色提醒：第一期不做。
7. ✅ 灰字（v0.2.4）：「已请 {成员} 接着」（消息流不写第 n/6）；「交给 {新成员}：你指定的」；空 give 不强写「没有交给下一位」。
8. ✅ 短复 vs 汇报卡（v0.2.4 / 契约待跟）：正式交付才出卡；招呼 / 澄清短自然语言。
