## 1. 设计定位

| 项 | 结论 |
|---|---|
| 入口 | 侧栏品牌区下方，虚线框「全部工具」按钮 + `Ctrl K` |
| 形态 | 居中浮层（不是从右侧滑出的 el-drawer），背后毛玻璃压暗 |
| 主交互 | 搜索优先：输入即筛，`↑↓` 选、`Enter` 进、`Esc` 关 |
| 为什么不用抽屉 | 侧栏只有 6 个一级入口，横向空间够；居中浮层对齐的是「启动台 / Spotlight」心智，比右滑抽屉更符合桌面应用的调用感 |

## 3. 关键决策与理由

**3.1 磁贴用横向，不用图标在上**

第一版是「大图标 + 名称 + 描述」竖向堆叠，实测 9 个工具占三行，第三行被底部提示条裁掉，而且每个磁贴内部留白太多、角标飘在右上角离内容很远。改成「图标 38px + 文字两行」横向排，**每个磁贴 60px 高，9 个工具刚好三行、一屏看完**，角标也自然落在名字右侧。

**3.2 分类配色只做语义区分，不做装饰**

| 分类 | 图标底色 | 理由 |
|---|---|---|
| 媒体 | 主色蓝 | 项目主业务 |
| 文档 | 青绿 `#0f766e` | 与现有 `--ff-clip-audio` 同源，视觉上区分文档域 |
| 直播 | 危险红 | 直播是"实时/在播"语义，红色有指示性 |
| 数据 | 紫 `#7c3aed` | 与现有 `--ff-syntax-bool` 同源 |
| 系统 | 中性灰 | 任务/Agent/设置属于元功能 |

深色主题下青绿提亮到 `#2dd4bf`、紫提亮到 `#a78bfa`，保证在 `#26282e` 底色上 ≥4.5:1。

**3.3 ffmpeg 缺失时的禁用态**

转换和直播两个磁贴整块降到 45% 不透明度、图标变灰、下方出现「⚠ 需要转换组件」小标签，点击不导航。这和现有 `SidebarItem.vue` 的 `gated` 逻辑一致（那边是 hover 提示「需要先安装转换组件」，这边改成常驻标签，因为浮层里没有 hover 的余裕）。底部状态栏同步显示「2 个需要转换组件」。

**3.4 角标规则**

- 任务中心：运行中任务数（蓝底白字），与现有侧栏 badge 同色 `--ff-badge-bg`
- Agent：「新」浅色小标签，与现有 `SidebarItem` 的 tag 一致

**3.5 空状态给搜索建议**

搜不到时不说"无结果"，给三个高命中词：「转码」「PDF」「推流」，并提示按 Esc 关闭 —— 浮层类交互最容易卡在搜不到又不知道怎么办。

## 5. 已踩的坑（实现时注意）

1. **`hidden` 属性会被 `display:grid/flex` 覆盖**。搜索框的清空按钮和"全部工具 · N"标题都用了 `hidden`，但 CSS 里给了 `display:grid` / `display:flex`，导致元素该隐藏时仍在。必须补 `[hidden] { display: none; }`。现有代码里同类写法值得全局排查一遍。
2. **居中要扣掉侧栏宽度**。`left: calc(var(--ff-sidebar-w) + (100vw - var(--ff-sidebar-w)) / 2)`，不能直接 `50%`，否则浮层会偏右压在右侧边缘。
3. **Wails 里 `backdrop-filter` 可用**（WebView2 是 Chromium 内核），但浮层面积大 + 毛玻璃，低端机可能有掉帧。建议保留 `backdrop-filter` 但要给「减少动效」时关掉模糊，只留半透明底色。
4. **`--wails-draggable`**。浮层不是标题栏，但要注意浮层内不能出现 `--wails-draggable: drag`；反过来侧栏品牌区本来就是 drag 区，新加的「全部工具」按钮必须显式 `--wails-draggable: no-drag`，否则点不动。

## 6. 待确认

- 「最近使用」存哪里？建议存 localStorage（`ff-toolbox-recent`），最多 5 条，与现有 `ff-sidebar-collapsed` 同类做法，不进 SQLite。
- 分类叫「数据」还是「开发」？现在只有 JSON 工具一个，后续若加正则/时间戳/编码转换，叫「数据」更稳。
- 需不需要「命令」这一类？搜索结果里现在只匹配工具名和关键词。如果以后要把 `/review` 这类指令也放进来，底部提示要改成 `↑↓` + `Tab` 切换工具/命令两组。
