---

## 一、现状的问题

对着实际跑起来的截图看，主要有五点：

**1. 侧栏太"素"，层级只在代码里，看不出来**

6 个入口加 1 个分隔线平铺，「转换 / 语音 / 文档 / 直播 / JSON」和「任务中心」是一组，「Agent / 设置」在底部，但视觉上分不出来 —— 因为没有分组标题，全靠那根 1px 分隔线。激活态是浅浅的蓝底 + 主色文字，**没有左侧指示条**，扫视时定位很慢。

**2. 侧栏底部 FFmpeg 状态是一行灰字**

`● 转换组件检测中…` 就一行，不可点，也不告诉用户「接下来该干嘛」。而它恰恰是**新用户第一个卡点**：组件没装，转换按钮是灰的。

**3. 顶栏只有「标题 + 一行灰色小字」和一个假装能用的搜索按钮**

`AppTitlebar.vue` 里 `onSearch()` 直接弹 `ElMessage.info('搜索功能开发中')`。放一个点了没反应的按钮，比不放更伤。

**4. 右栏设置面板全是"平铺"**

格式按「视频 / 音频 / 图片」三个页签切换，每个页签里再平铺 6~9 个格式块。问题：
- 格式块只有边框，选中的那个**只靠边框变蓝**，一眼扫不出来；
- 分组标题（PDF / 文档 / 表格 / 演示）是灰色小字贴在网格上方，和格式块没有包裹关系；
- 「保存到」的路径框是纯文本 + 一个按钮，不像输入框；
- 底部主按钮 `转换` 在禁用态是淡蓝色，仍然像可点的。

**5. 卡片全是直角化大平面**

`.panel` 只有 1px 边框和 10px 圆角，没有阴影层次。整个界面是一层层白底叠白底，主体（列表）和辅助（右栏）的权重一样。

## 二、改了什么

### 2.1 左侧栏

| 项 | 现状 | 新版 |
|---|---|---|
| 宽度 | 200px | **216px**（多了分组标题和左侧竖条，200px 会挤） |
| 分组 | 一根分隔线 | **「工作台」/「管理」两个小标题**，语义分组 |
| 激活态 | 浅蓝底 + 蓝字 | 浅蓝底 + 蓝字 + **左侧 3px 竖直指示条** + 字重 550 |
| 行高 | 36px | **38px**（触摸/鼠标都更稳） |
| 图标 | 16px，透明度恒定 | 17px，未选中 `opacity:.85`，选中恢复 100% |
| FFmpeg 状态 | 一行灰字 | **可点卡片**：状态点 + 一句话 + 「安装转换组件 →」 |
| 品牌区 | 32px 方块 | 34px 圆角方块，蓝色→紫色微渐变 + 内阴影，更像应用图标 |

激活指示条是关键：现在 6 个菜单项高度一致、图标全线性、颜色都一样，**只有一个 3px 竖条能在余光里定位**。

### 2.2 顶栏

| 项 | 现状 | 新版 |
|---|---|---|
| 高度 | 40px | **48px**（要塞下 30px 的搜索框） |
| 背景 | 透明（跟内容同色） | `--ff-bg-surface` 白底，与内容区分层 |
| 搜索 | 一个图标按钮，点了弹「开发中」 | **220px 胶囊输入框** + `Ctrl K` 提示 |
| 右侧 | 主题 + 搜索 | 主题 + 更多（`⋯`） |
| 标题 | 14px 半粗 + 12px 灰字 | 同字号，间距收紧，副标题用基线对齐 |

搜索框现在是**真的输入框**，不是假按钮。如果后端一时接不上，建议先做成「输入后跳到任务中心并带上关键词」——比弹「开发中」诚实。

### 2.3 右栏设置面板

这是改动最集中的地方：

**a) 格式块改成卡片式，选中态明确**

```
未选中              选中
┌────────┐        ┌────────┐  ← 主色边框 + 主色浅底
│  MP4   │        │  MP4   │     + 内侧 1px 主色描边
│ H.264  │        │ H.264  │     + 文字转主色
└────────┘        └────────┘
```

三个视觉信号叠加（边框、底色、文字色），扫视时不用逐个比对。悬停加 `translateY(-1px)` 微抬。

**b) 分组加小标题，和网格形成包裹关系**

`常用 / 视频 / 音频` 作为 10.5px 全大写小标题，间距收紧到 7px，让「标题 + 网格」成为一个视觉块。

**c) 「保存到」路径框做成真输入框的样子**

现状是纯文本。新版用等宽字体 + 浅灰底 + 边框，一眼看出"这是个路径"，旁边按钮对齐同高。

**d) 底部主按钮加大一号，禁用态真正"看起来不可点"**

40px 高、16px 图标、主色到深主色的阴影。禁用态从"淡蓝"改成"主色 34% 混白底"，明确灰掉。下面那行提示文字，警告时用 `--ff-warning-text`（橙）而不是灰。

**e) 面板本身加了 12px 圆角和极浅阴影**

和左侧列表卡片区分开：列表是主体（扁、大），右栏是工具面板（略抬起）。

### 2.4 内容区

- 卡片统一 `--ff-radius-xl`(12px) + `--ff-shadow-card`（两层极浅阴影），不再是白底叠白底；
- 列表行 hover 有 9px 圆角浅底，操作按钮**只在 hover 时淡入**（省掉平时的一排灰图标）；
- 进度条 3px，按状态变色（进行中蓝 / 失败红 / 完成绿）；
- 状态胶囊统一 5px 圆角小标签，五色语义（进行中 / 完成 / 失败 / 排队）。

### 2.5 任务中心

四张统计卡加了语义色：运行中蓝、完成绿、失败红，数字 24px 半粗 + `tabular-nums`（数字跳动时不抖宽度）。

## 三、新增的设计变量

```css
--ff-sidebar-w: 216px;        /* 原 200px */
--ff-titlebar-h: 48px;        /* 原 40px */
--ff-right-w: 332px;          /* 右栏固定宽，原来靠 flex 撑 */
--ff-nav-active-bg: #eef3ff;  /* 导航激活底，比 --ff-primary-soft 略深 */
--ff-nav-accent: #3b6ef5;     /* 激活竖条 / 激活图标 */
--ff-ring: 0 0 0 3px rgba(59,110,245,.16);   /* 输入框聚焦环 */
--ff-shadow-card: 0 1px 2px rgba(16,20,28,.04), 0 4px 12px -6px rgba(16,20,28,.08);
--ff-border-soft: #eceef2;    /* 卡片内部分隔线，比 --ff-border 更浅 */
```

深色主题下这 7 个都有对应值，原型里已实现（截图：[深色](new-convert-dark.png)）。

## 四、响应式（已实测）

窗口最小 1024×680 是 Wails 配置的 `MinWidth/MinHeight`，实测三档：

| 窗口宽 | 行为 |
|---|---|
| ≥1120px | 完整显示：计数、分段、搜索框 130px |
| 1000–1120px | 隐藏「5 个文件 · 8 条记录」，搜索框缩到 84px |
| <1000px | 隐藏「全部/进行中/失败」分段（可考虑移到标题下方做第二行） |

1024×680 下的效果：[截图](new-min.png)。第一版在这个尺寸下**列表头挤成两行**（"全部/进行中/失败"和"添加文件"都竖着断行），加 `white-space: nowrap` + 媒体查询才修好。

## 五、实现注意

1. **`--wails-draggable`**：顶栏是 drag 区，新加的搜索框、主题按钮、更多按钮都必须显式 `--wails-draggable: no-drag`，否则点不动。侧栏品牌区同理，折叠按钮也要 no-drag。
2. **侧栏宽度变了要同步**：`AppSidebar.vue` 用的是 `var(--ff-sidebar-w)`，但 `cat-away`（Cat 页收起）的动画里有硬编码的 `250ms` 和 0 宽度，改宽度不影响逻辑，但 `--ff-sidebar-w-collapsed: 56px` 这个折叠态要一起调。
3. **顶栏高度 48px 影响 `traffic-space`**：`AppSidebar.vue` 里 macOS 红绿灯预留区用的是 `var(--ff-titlebar-h)`，自动跟随。
4. **不要动 `convert-v2.css`**：那 51KB 里是转换页的完整样式，本次外壳改造只需覆盖 `.panel` 基础样式和容器，逐页迁移风险大。建议先改外壳（侧栏 + 顶栏 + `.panel` 变量），转换页内部保持不动。
5. **搜索框别再做假按钮**：要么接真功能，要么先隐藏。

## 六、改动量与优先级

| 优先级 | 文件 | 改动 |
|---|---|---|
| **P0** | `styles/tokens.css` | 加 7 个变量 + 改 2 个值 |
| **P0** | `layout/AppSidebar.vue` | 分组标题、激活竖条、状态卡片（约 60 行 CSS + 10 行模板） |
| **P0** | `layout/AppTitlebar.vue` | 48px 高、白底、搜索框（约 50 行） |
| **P1** | `App.vue` | `--ff-sidebar-w` 相关布局、内容区 padding 从 20/24 改 14/16 |
| **P1** | `components/convert/ConvertFormatPanel.vue` | 格式块选中态（约 20 行 CSS） |
| **P2** | `views/TaskCenter.vue` | 统计卡语义色（约 15 行） |

P0 三项就能让整个应用"变样"，且不碰任何业务逻辑，改完 `npm run build` 就能看效果。P1/P2 是细部。

**风险**：`convert-v2.css` 里可能对 `.panel` 有覆盖，改基础样式后要逐页目检一次（转换页 / 文档页 / 任务中心 / 设置页）。
